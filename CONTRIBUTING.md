# Contributing

Contributions that improve the audit workflow, clarify guidance, or correct inaccurate security advice are welcome.

## Before you contribute

- Open an issue or discussion for broad changes so the scope can be agreed on first.
- Keep changes focused on the skill, its references, or its documentation.
- Never include real credentials, private user data, or details that could identify an unreported vulnerability.

## Editing guidance

- Keep `SKILL.md` concise and use `references/` for detailed, category-specific checks.
- Make security guidance actionable, evidence-based, and clear about what is verified versus unverified.
- Link to authoritative, maintained sources when adding or changing security recommendations.
- Keep the README, skill instructions, and reference links consistent with one another.
- Preserve the read-only-by-default workflow and authorization boundaries.

## Submitting changes

1. Make the smallest change that addresses the issue.
2. Review the rendered Markdown and check links, paths, and code examples.
3. Describe what changed and any checks you performed in your pull request.

This repository has no application build or automated test suite. For documentation-only changes, review the affected Markdown files and verify that referenced files exist.
